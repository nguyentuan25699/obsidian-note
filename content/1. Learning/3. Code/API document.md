## 1. API Documentation
- API documentation is a technical content deliverable, containing instructions about how to effectively use and integrate with an API.
- It’s a concise reference manual containing all the information required to work with the API, with details about the functions, classes, return types, arguments and more, supported by tutorials and examples.
- API Documentation has traditionally been done using regular content creation and maintenance tools and text editors.
___

The information must be required to work with the API:
- URL
- Method
- Data of the request (name, type, description)
- Authentication requests
- Configuring request headers (Ex: Content-type)
- Response example
___ 

## 2. Why Document APIs?
- API documentation is very important because it aims to help clients or users implement API and understand how it works, makes it easier for users to interact with the code.
- API documentation is to cover everything a client would need to know for practical purposes and helps them if they makes wrong steps somewhere along the way when using your APIs.
- And good documentation encourages potential clients to use or buy your service.
___
- **Improved User Adoption**: If you get your documentation right, more people will find value in your services easily, leading to better growth and adoption.
- **Increased Awareness**: If users can easily and quickly learn to use your APIs, they’ll be your biggest proponents, leading to the network effect.
- **Saves Support Time and Costs**: If you arm uses with detailed documentation to get started, you’ll save your team countless hours responding to support emails and calls.
- **Easier Maintenance**: It helps your internal teams know the details of your resources, methods, and their associated requests and responses, making maintenance and updates quicker.
