# Buổi 12 — Ôn tập sâu: So sánh hơn / So sánh nhất

## 1. Nhắc lại nhanh công thức gốc

|              | Tính từ ngắn      | Tính từ dài         |
| ------------ | ----------------- | ------------------- |
| So sánh hơn  | adj + er (+ than) | more + adj (+ than) |
| So sánh nhất | the + adj + est   | the most + adj      |

Bất quy tắc: good → better → the best | bad → worse → the worst

## 2. Điểm mở rộng đáng lưu ý

### 2.1 So sánh bằng (as...as)

Diễn tả 2 thứ ngang bằng nhau về mức độ.

Công thức: as + adj (nguyên dạng, không chia so sánh) + as

- This solution is as efficient as the previous one. (hiệu quả ngang nhau)

Phủ định: not as/so + adj + as

- This server is not as fast as the new one. (không nhanh bằng)

Lưu ý quan trọng: cấu trúc as...as không bao giờ đi kèm "more" hay bất kỳ dạng so sánh hơn nào khác — chỉ đơn giản là as + adj (nguyên dạng) + as.

### 2.2 Tính từ 2 âm tiết — vùng "xám", có thể dùng cả 2 cách

Một số tính từ 2 âm tiết không tận cùng bằng "-y" có thể chấp nhận cả 2 dạng so sánh (-er hoặc more), tùy mức độ phổ biến trong thực tế sử dụng.

- simple → simpler / more simple (cả 2 đều được chấp nhận, nhưng "simpler" phổ biến hơn)
- quiet → quieter / more quiet (tương tự)

TOEIC thường ưu tiên dạng phổ biến hơn, nhưng không coi dạng còn lại là sai hoàn toàn.

### 2.3 "The + so sánh hơn..., the + so sánh hơn..." — cấu trúc song song

Diễn tả "càng... càng...", khá hay gặp trong TOEIC Part 5/6 và giao tiếp công việc.

- The more efficient the code is, the faster the app runs. (code càng hiệu quả, app càng chạy nhanh)
- The sooner we fix this, the better. (càng sớm sửa, càng tốt)

### 2.4 Nhấn mạnh mức độ chênh lệch (much/a lot/slightly + so sánh hơn)

Thêm từ nhấn mạnh trước dạng so sánh hơn để chỉ mức độ chênh lệch.

- This version is much faster than the old one. (nhanh hơn nhiều)
- The new design is slightly better. (tốt hơn một chút)

## 3. Lỗi thường gặp khi ôn tập

Lỗi 1: thêm "more" vào cấu trúc so sánh bằng (as...as), nhầm sang so sánh hơn.

Sai: This library is as more efficient as the old one. Đúng: This library is as efficient as the old one.

Lỗi 2: trộn lẫn "not as...as" (so sánh bằng phủ định) với so sánh hơn (better/faster), dẫn đến câu sai cấu trúc.

Sai: This approach is not better as the one we used last time. Đúng: This approach is not as good as the one we used last time. (nếu muốn dùng "better", viết lại hoàn toàn: This approach is worse than the one we used last time.)

Lỗi 3: quên "than" sau dạng so sánh hơn khi trộn nhiều cấu trúc trong cùng bài tập.

Sai: This code is more clean the previous version. Đúng: This code is cleaner than the previous version.

Lỗi 4: nhầm dạng so sánh hơn của tính từ ngắn (-er) với tính từ dài (more) — vẫn còn sai lại dù đã học từ buổi 4.

Sai: This code is more clean than the previous version. Đúng: This code is cleaner than the previous version. ("clean" là tính từ ngắn, 1 âm tiết)

## 4. Bài tập ôn sâu đã làm (để ôn lại)

Vòng 1:

1. This library is as efficient as the old one — no real difference in performance.
2. The earlier we deploy, the fewer risks we take.
3. Our new server is much faster than the previous one.
4. This solution is more simple (hoặc simpler), so most developers prefer it.
5. This approach is not as good as the one we used last time.
6. The update is slightly more reliable than the previous version.

Vòng 2 (tách riêng từng cấu trúc để luyện kỹ):

Nhóm A — So sánh hơn (luôn có "than"): 7. This code is cleaner than the previous version. (clean = tính từ ngắn, dùng -er) 8. Our new process is more efficient than the old one. (efficient = tính từ dài, dùng more)

Nhóm B — So sánh bằng phủ định (not as...as): 9. This tool is not as powerful as the one we used before. 10. The result is not as accurate as we expected.

Nhóm C — Cấu trúc "The...the..." (càng...càng...): 11. The faster you respond, the happier the client will be.
