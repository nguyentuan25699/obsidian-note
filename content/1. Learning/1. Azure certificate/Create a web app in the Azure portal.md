# Why use the Azure portal?
___
The first step in hosting your web application is to create a web app (an Azure App Service app) inside your Azure subscription.
	Bước đầu tiên để triển khai ứng dụng web của bạn là tạo một ứng dụng web (ứng dụng Azure App Service) bên trong gói đăng ký Azure của bạn.
There are several ways you can create a web app. You can use the Azure portal, the Azure Command Line Interface (CLI), a script, or an integrated development environment (IDE) like Visual Studio.
	Có nhiều cách để tạo một ứng dụng web. Bạn có thể sử dụng cổng thông tin Azure, giao diện dòng lệnh Azure (CLI), tập lệnh hoặc môi trường phát triển tích hợp (IDE) như Visual Studio.
The information in this unit discusses how to use the Azure portal to create a web app, and you use this information to create a web app in the next exercise. For this module, we demonstrate using the Azure portal because it's a graphical experience, which makes it a great learning tool. The portal helps you discover available features, add other resources, and customize existing resources.
	Thông tin trong phần này thảo luận về cách sử dụng cổng thông tin Azure để tạo ứng dụng web, và bạn sẽ sử dụng thông tin này để tạo ứng dụng web trong bài tập tiếp theo. Đối với mô-đun này, chúng tôi trình bày cách sử dụng cổng thông tin Azure vì nó có giao diện đồ họa, khiến nó trở thành một công cụ học tập tuyệt vời. Cổng thông tin giúp bạn khám phá các tính năng có sẵn, thêm các tài nguyên khác và tùy chỉnh các tài nguyên hiện có.
# What is Azure App Service?
___
Azure App Service is a fully managed web application hosting platform. This [[Platform as a service (PaaS)]] offered by Azure allows you to focus on designing and building your app while Azure takes care of the infrastructure to run and scale your applications.
	Azure App Service là một nền tảng lưu trữ ứng dụng web được quản lý hoàn toàn. Nền tảng dưới dạng dịch vụ (PaaS) này do Azure cung cấp cho phép bạn tập trung vào việc thiết kế và xây dựng ứng dụng của mình trong khi Azure đảm nhiệm cơ sở hạ tầng để vận hành và mở rộng quy mô ứng dụng.
# Deployment slots
___
Using the Azure portal, you can easily add **deployment slots** to an App Service web app. For instance, you can create a **staging** deployment slot where you can push your code to test on Azure. Once you're happy with your code, you can easily **swap** the staging deployment slot with the production slot. All it takes is a few mouse clicks in the Azure portal.
	Sử dụng cổng thông tin Azure, bạn có thể dễ dàng thêm các khe triển khai vào ứng dụng web App Service. Ví dụ, bạn có thể tạo một khe triển khai thử nghiệm để đẩy mã của mình lên Azure để kiểm thử. Sau khi hài lòng với mã của mình, bạn có thể dễ dàng hoán đổi khe triển khai thử nghiệm với khe triển khai sản xuất. Tất cả chỉ cần một vài cú nhấp chuột trong cổng thông tin Azure.

# Continuous integration/deployment support
___
The Azure portal provides out-of-the-box continuous integration and deployment with Azure Repos, GitHub, Bitbucket, FTP, or a local Git repository on your development machine. You can connect your web app with any of the preceding sources, and App Service does the rest for you. It automatically syncs your code and any future changes on the code into the web app. Furthermore, with Azure Repos, you can define your own build and release process. A full process that compiles your source code, runs the tests, builds a release, and finally deploys the release into your web app every time you commit the code. All that happens implicitly, without any need for you to intervene.
	Cổng thông tin Azure cung cấp khả năng tích hợp và triển khai liên tục sẵn có với Azure Repos, GitHub, Bitbucket, FTP hoặc kho lưu trữ Git cục bộ trên máy tính phát triển của bạn. Bạn có thể kết nối ứng dụng web của mình với bất kỳ nguồn nào nêu trên, và App Service sẽ thực hiện phần còn lại cho bạn. Nó tự động đồng bộ hóa mã của bạn và bất kỳ thay đổi nào trong tương lai đối với mã vào ứng dụng web. Hơn nữa, với Azure Repos, bạn có thể xác định quy trình xây dựng và phát hành của riêng mình. Một quy trình hoàn chỉnh bao gồm biên dịch mã nguồn, chạy thử nghiệm, xây dựng bản phát hành và cuối cùng triển khai bản phát hành vào ứng dụng web của bạn mỗi khi bạn cam kết mã. Tất cả điều đó diễn ra một cách ngầm định, mà không cần bạn can thiệp.

# Integrated Visual Studio publishing and FTP publishing
___
In addition to being able to set up continuous integration/deployment for your web app, you can always benefit from the tight integration with Visual Studio to publish your web app to Azure via Web Deploy technology. App Service also supports FTP-based publishing for more traditional workflows.
	Ngoài khả năng thiết lập tích hợp/triển khai liên tục cho ứng dụng web của bạn, bạn luôn có thể tận dụng sự tích hợp chặt chẽ với Visual Studio để xuất bản ứng dụng web lên Azure thông qua công nghệ Web Deploy. App Service cũng hỗ trợ xuất bản dựa trên FTP cho các quy trình làm việc truyền thống hơn.

# Built-in autoscale support (automatic scale-out based on real-world load)
___
The ability to scale up/down or scale out is baked into the web app. Depending on the web app's usage, you can scale your app up/down by increasing/decreasing the resources of the underlying machine that's hosting your web app. Resources can be the number of cores or the amount of RAM available. On the other hand, you can scale out your app by increasing the number of machine instances that are running your web app.
	Khả năng mở rộng quy mô (tăng/giảm quy mô hoặc mở rộng phạm vi) đã được tích hợp sẵn trong ứng dụng web. Tùy thuộc vào mức độ sử dụng ứng dụng web, bạn có thể mở rộng quy mô ứng dụng bằng cách tăng/giảm tài nguyên của máy chủ lưu trữ ứng dụng web. Tài nguyên có thể là số lõi xử lý hoặc dung lượng RAM hiện có. Mặt khác, bạn có thể mở rộng phạm vi ứng dụng bằng cách tăng số lượng máy ảo đang chạy ứng dụng web của mình.

# Creating a web app
___
When you're ready to run a web app on Azure, you can visit the Azure portal and create a **Web App** resource. Creating a web app allocates a set of hosting resources in App Service. You can use these resources to host any web-based application Azure supports, whether it's ASP.NET Core, Node.js, Java, Python, and so on.
	Khi bạn đã sẵn sàng chạy ứng dụng web trên Azure, bạn có thể truy cập cổng thông tin Azure và tạo tài nguyên Ứng dụng web. Việc tạo ứng dụng web sẽ phân bổ một tập hợp các tài nguyên lưu trữ trong App Service. Bạn có thể sử dụng các tài nguyên này để lưu trữ bất kỳ ứng dụng web nào mà Azure hỗ trợ, cho dù đó là ASP.NET Core, Node.js, Java, Python, v.v.
The Azure portal provides a wizard to create a web app. This wizard requires the following fields:
	Cổng thông tin Azure cung cấp trình hướng dẫn để tạo ứng dụng web. Trình hướng dẫn này yêu cầu các trường sau:

# Operating systems
___
If you're deploying your app as code, many of the available runtime stacks are limited to one operating system or the other. After you choose a runtime stack, the toggle will indicate whether or not you have a choice of operating system. If your target runtime stack is available on both operating systems, select the one that you use to develop and test your application.
	Nếu bạn triển khai ứng dụng của mình dưới dạng mã, nhiều ngăn xếp thời gian chạy có sẵn chỉ giới hạn ở một hệ điều hành nhất định. Sau khi bạn chọn một ngăn xếp thời gian chạy, nút chuyển đổi sẽ cho biết bạn có thể lựa chọn hệ điều hành hay không. Nếu ngăn xếp thời gian chạy mục tiêu của bạn có sẵn trên cả hai hệ điều hành, hãy chọn hệ điều hành mà bạn sử dụng để phát triển và kiểm thử ứng dụng của mình.

If your application is packaged as a container, specify the operating system in your container.
	Nếu ứng dụng của bạn được đóng gói dưới dạng container, hãy chỉ định hệ điều hành trong container đó.

# App Service plans
___
An App Service plan is a set of virtual server resources that run App Service apps. A plan's size (sometimes referred to as its sku or pricing tier) determines the performance characteristics of the virtual servers that run the apps assigned to the plan, and the App Service features to which those apps have access. Every App Service web app you create must be assigned to a single App Service plan that runs it.
	Gói dịch vụ App Service là một tập hợp các tài nguyên máy chủ ảo chạy các ứng dụng App Service. Kích thước của gói (đôi khi được gọi là SKU hoặc bậc giá) xác định các đặc tính hiệu suất của các máy chủ ảo chạy các ứng dụng được gán cho gói đó, và các tính năng App Service mà các ứng dụng đó có quyền truy cập. Mỗi ứng dụng web App Service bạn tạo phải được gán cho một gói dịch vụ App Service duy nhất để chạy nó.

A single App Service plan can host multiple App Service web apps. In most cases, the number of apps you can run on a single plan is limited by the apps' performance characteristics and the plan's resource limitations.
	Một gói dịch vụ App Service duy nhất có thể chứa nhiều ứng dụng web App Service. Trong hầu hết các trường hợp, số lượng ứng dụng bạn có thể chạy trên một gói duy nhất bị giới hạn bởi các đặc tính hiệu suất của ứng dụng và giới hạn tài nguyên của gói.

App Service plans determine the App Service's unit of billing. The size of each App Service plan in your subscription, in addition to the bandwidth resources the apps deployed to those plans use, determines the price you pay. The number of web apps deployed to your App Service plans has no effect on your bill.
	Gói dịch vụ App Service xác định đơn vị tính phí của App Service. Kích thước của mỗi gói dịch vụ App Service trong gói đăng ký của bạn, cùng với tài nguyên băng thông mà các ứng dụng được triển khai trên các gói đó sử dụng, sẽ xác định giá bạn phải trả. Số lượng ứng dụng web được triển khai trên các gói dịch vụ App Service của bạn không ảnh hưởng đến hóa đơn của bạn.

You can use any of the available Azure management tools to create an App Service plan. When you create a web app via the Azure portal, the wizard helps you to create a new plan at the same time if you don't already have one.
	Bạn có thể sử dụng bất kỳ công cụ quản lý Azure nào có sẵn để tạo gói dịch vụ App Service. Khi bạn tạo ứng dụng web thông qua cổng Azure, trình hướng dẫn sẽ giúp bạn tạo gói mới cùng lúc nếu bạn chưa có gói nào.
